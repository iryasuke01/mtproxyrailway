# پروکسی MTProto تلگرام برای Railway

یک پروژه کوچک و مستقل که با Docker یک پروکسی MTProto (نرم‌افزار mtg نسخه 2.1.7) را اجرا می‌کند. همه‌چیز با متغیرهای محیطی تنظیم می‌شود و Secret هرگز داخل کد قرار نمی‌گیرد.

---

## ⚠️ قبل از هر کاری این را بخوانید (سیاست Railway)

سیاست استفاده قابل‌قبول Railway (Acceptable Use Policy) در فهرست سوءاستفاده‌ها صراحتاً «اجرای پروکسی یا سرویس‌های ناشناس‌سازی» را ممنوع کرده است: https://railway.com/legal/acceptable-use

- در انجمن Railway گزارش‌هایی هست که حساب‌هایی که پروکسی/VPN اجرا کرده‌اند محدود شده‌اند و Railway گفته این محدودیت قابل برگشت نیست.
- پشتیبانی Railway درباره MTProto هم تأیید یا رد صریح نداده و فقط گفته به نوع استفاده (شخصی یا عمومی، مقیاس) بستگی دارد. یعنی ممکن است در عمل تحمل شود، ولی تضمینی نیست.
- پیامد بدتر محدود شدن، از دست رفتن **همه‌ی پروژه‌های دیگر** همان حساب است.

**پیشنهاد:** اگر روی حسابتان پروژه مهم دیگری دارید، این را روی یک حساب جداگانه امتحان کنید یا روی سرویس دیگری (مثلاً یک VPS) اجرا کنید. این پروژه روی هر هاستی که Docker بتواند اجرا کند کار می‌کند؛ فقط بخش TCP Proxy مخصوص Railway است.

## معماری و دلیل انتخاب

| گزینه | وضعیت | نتیجه |
|---|---|---|
| پروژه رسمی تلگرام (MTProxy، زبان C) | مخزن Release/Tag ندارد؛ README خودش می‌گوید ایمیج Docker رسمی قدیمی است. در کانتینر پشت NAT معمولاً به تنظیم `--nat-info` و آدرس‌های داخلی/عمومی نیاز دارد که روی Railway ثابت نیست. | انتخاب نشد |
| **mtg نسخه 2** (Go) | فعال و نگهداری می‌شود، یک فایل اجرایی کوچک، پشتیبانی از FakeTLS (شبیه HTTPS، سخت‌تر قابل شناسایی)، بدون نیاز به فایل‌های پیکربندی خارجی. | **انتخاب شد** |

- mtg همان پروتکل MTProto پروکسی تلگرام را پیاده می‌کند و برنامه رسمی تلگرام به آن وصل می‌شود.
- نسخه با `ARG MTG_VERSION` در Dockerfile ثابت شده (عمداً `latest` نیست).
- **تفاوت با درخواست اولیه:** نرم‌افزار رسمی فایل‌های `proxy-secret` و `proxy-multi.conf` را از تلگرام دانلود می‌کند، ولی mtg چنین فایلی ندارد. پس «دریافت و به‌روزرسانی فایل پیکربندی تلگرام» اینجا موضوعیت ندارد و به‌جایش ارتباط با سرورهای تلگرام را پایش می‌کنیم.
- mtg قابلیت «تگ تبلیغاتی» (کانال حمایت‌شده) ندارد.
- Railway فقط Healthcheck از نوع HTTP دارد؛ برای سرویس TCP پایش سلامت داخل `entrypoint.sh` انجام می‌شود.
- Volume **اختیاری** است. اگر Volume نبود، Secret را با متغیر `MTG_SECRET` نگه دارید.

### فایل‌های پروژه

```
Dockerfile        ساخت ایمیج (ساخت mtg از سورس رسمی با نسخه ثابت)
entrypoint.sh     ساخت Secret و تنظیمات، اجرای mtg، راه‌اندازی مجدد، پایش و Logs
railway.toml      تنظیمات Railway (روش ساخت و سیاست راه‌اندازی مجدد)
.dockerignore     فایل‌هایی که وارد ایمیج نمی‌شوند
.gitignore        جلوگیری از آپلود Secret و فایل‌های محلی
README.md         همین راهنما
```

## مرحله ۱: ساخت مخزن GitHub با گوشی

1. در مرورگر گوشی به github.com بروید و وارد حسابتان شوید (اگر حساب ندارید Sign up کنید).
2. بالا روی علامت **+** بزنید و **New repository** را انتخاب کنید.
3. نام را مثلاً `mtproxy-railway` بگذارید و حالت **Private** را انتخاب کنید. (Secret داخل کد نیست، ولی خصوصی بودن بهتر است.)
4. روی **Create repository** بزنید.
5. فایل‌ها را آپلود کنید. دو روش:
   - **روش آسان:** فایل ZIP را داخل گوشی باز کنید (با برنامه Files)، بعد در GitHub روی **uploading an existing file** بزنید و فایل‌ها را انتخاب کنید.
   - **اگر فایل‌هایی که با نقطه شروع می‌شوند (`.gitignore` و `.dockerignore`) در انتخاب‌گر فایل دیده نشدند:** در GitHub روی **Add file ← Create new file** بزنید، نام فایل را دقیقاً `.gitignore` بنویسید، محتوا را کپی/پیست کنید و **Commit changes** بزنید. برای `.dockerignore` هم همین کار را بکنید.
6. در پایان روی **Commit changes** بزنید.

نکته: لازم نیست دسترسی اجرایی فایل‌ها را تنظیم کنید؛ Dockerfile خودش این کار را می‌کند.

## مرحله ۲: اتصال GitHub به Railway

1. در railway.com وارد شوید.
2. **New Project ← Deploy from GitHub repo** را بزنید.
3. اگر خواست، دسترسی Railway به GitHub را بدهید (Configure GitHub App) و فقط همین مخزن را انتخاب کنید.
4. مخزن `mtproxy-railway` را انتخاب کنید و **Deploy** بزنید.
5. Railway فایل Dockerfile را خودش پیدا می‌کند. اولین Build چند دقیقه طول می‌کشد.

## مرحله ۳: متغیرهای محیطی

محل: روی سرویس بزنید ← تب **Variables** ← **New Variable** (یا **Raw Editor**).

| متغیر | لازم؟ | پیش‌فرض | توضیح |
|---|---|---|---|
| `MTG_SECRET` | توصیه می‌شود | ساخته می‌شود | رشته hex که با `ee` شروع می‌شود. اگر Volume ندارید حتماً بعد از اولین اجرا آن را از Logs کپی و اینجا ثبت کنید. |
| `MTG_PORT` | خیر | `8443` | پورت داخلی برنامه. باید با پورت TCP Proxy یکی باشد. |
| `MTG_FAKE_TLS_DOMAIN` | خیر | `www.google.com` | دامنه‌ای که برای ساخت Secret جدید استفاده می‌شود (فقط هنگام ساخت). |
| `MTG_CONCURRENCY` | خیر | `1024` | سقف اتصال هم‌زمان. برای مصرف کم منابع. |
| `MTG_BIND_HOST` | خیر | `0.0.0.0` | اگر اتصال برقرار نشد `::` را امتحان کنید. |
| `MTG_PREFER_IP` | خیر | `prefer-ipv4` | یکی از `prefer-ipv4`، `prefer-ipv6`، `only-ipv4`، `only-ipv6` |
| `LOG_SECRET` | خیر | `true` | با `false` شدن، Secret در Logs چاپ نمی‌شود. |
| `HEALTH_INTERVAL` | خیر | `30` | فاصله بررسی سلامت (ثانیه) |
| `HEARTBEAT_MIN` | خیر | `15` | فاصله گزارش دوره‌ای (دقیقه) |

**هرگز** Secret را داخل فایل‌های مخزن ننویسید.

### Volume (اختیاری)

اگر Railway در پلن شما اجازه می‌دهد: روی بوم پروژه، سرویس را انتخاب کنید و یک **Volume** بسازید و مسیر اتصال را `/data` بگذارید. با Volume، Secret ساخته‌شده بعد از Restart و Deploy ثابت می‌ماند. (من نتوانستم تأیید کنم Volume یا TCP Proxy در پلن رایگان/آزمایشی شما فعال است؛ در پنل خودتان ببینید.) اگر Volume نداشتید، فقط `MTG_SECRET` را ثبت کنید.

## مرحله ۴: فعال کردن TCP Proxy

1. روی سرویس بزنید ← **Settings** ← بخش **Networking**.
2. روی **TCP Proxy** بزنید.
3. در کادر پورت عدد **8443** را بنویسید (همان `MTG_PORT`). این «پورت داخلی» است.
4. Railway یک آدرس و پورت عمومی می‌سازد، مثلاً `xxx.proxy.rlwy.net:15140`. **پورت عمومی** (مثل 15140) با پورت داخلی (8443) فرق دارد و در لینک تلگرام باید پورت عمومی بیاید.
5. بعد از فعال شدن، سرویس را **Redeploy** کنید تا متغیرهای `RAILWAY_TCP_PROXY_DOMAIN` و `RAILWAY_TCP_PROXY_PORT` در برنامه بیایند.

---

## مرحله ۵: گرفتن Server، Port، Secret و لینک

1. سرویس ← تب **Deployments** ← آخرین Deployment ← **View Logs**.
2. بلوک «اطلاعات اتصال» را پیدا کنید. این بلوک فقط وقتی چاپ می‌شود که TCP Proxy فعال باشد و مقدارهایش واقعی هستند:

```
Server : <دامنه TCP Proxy>
Port   : <پورت عمومی>
Secret : <secret>
لینک   : tg://proxy?server=...&port=...&secret=...
```

3. روی لینک `tg://proxy...` یا لینک `https://t.me/proxy...` در گوشی بزنید. تلگرام صفحه افزودن پروکسی را باز می‌کند.
4. اگر Volume ندارید، Secret را همین‌جا در `MTG_SECRET` ثبت کنید.
5. وقتی لینک را ذخیره کردید، `LOG_SECRET=false` بگذارید.

اگر بلوک اطلاعات نیامد و پیام «TCP Proxy هنوز فعال نشده» دیدید، مرحله ۴ را کامل کنید و Redeploy بزنید. هیچ لینک ساختگی در جایی وجود ندارد.

## پایش و پیام‌های Logs

برنامه هر `HEALTH_INTERVAL` ثانیه بررسی می‌کند و فقط هنگام تغییر وضعیت پیام می‌دهد:

- زنده بودن پردازش mtg و باز بودن پورت داخلی (بعد از ۳ بار شکست پیاپی، mtg دوباره راه‌اندازی می‌شود)
- دسترسی به سرورهای تلگرام (پورت 443)
- فضای دیسک، حافظه و CPU
- راه‌اندازی مجدد خودکار با فاصله فزاینده؛ اگر ۵ بار پشت سر هم زود خاموش شود، سرویس متوقف می‌شود تا Railway تصمیم بگیرد (حداکثر ۱۰ تلاش در `railway.toml`)
- هر ۱۵ دقیقه یک گزارش: تعداد اتصال‌های فعال، حافظه، دیسک

### خطاهای رایج

| علامت در Logs | علت و راه‌حل |
|---|---|
| «پورت داخلی با Application Port یکی نیست» | پورت TCP Proxy را در Settings روی همان `MTG_PORT` (پیش‌فرض 8443) بگذارید. |
| «TCP Proxy هنوز فعال نشده» | مرحله ۴ را انجام دهید و Redeploy کنید. |
| «فرمت Secret درست نیست» | `MTG_SECRET` باید hex باشد و با `ee` شروع شود. برای Secret جدید متغیر را حذف کنید. |
| «mtg متوقف شد (کد 137)» | حافظه تمام شده؛ `MTG_CONCURRENCY` را کم کنید. |
| «سرورهای تلگرام در دسترس نیستند» | معمولاً مشکل موقت شبکه Railway است؛ اگر ادامه یافت Redeploy یا تغییر Region را امتحان کنید. |
| سرویس سالم است ولی تلگرام وصل نمی‌شود | `MTG_BIND_HOST=::` را امتحان کنید؛ مطمئن شوید پورت عمومی (نه داخلی) را در لینک گذاشته‌اید. |
| Build خطا می‌دهد | Logs بخش Build را ببینید. معمولاً مشکل دانلود ماژول Go یا فقدان Dockerfile در ریشه مخزن است. |

## سالم بودن سرویس ≠ قابل دسترس بودن از شبکه شما

- «سالم» یعنی پردازش بالاست، پورت داخلی پاسخ می‌دهد و تلگرام از سمت سرور قابل دسترس است.
- «قابل دسترس» یعنی دستگاه **شما** از اینترنت/اپراتور خودتان به آدرس و پورت Railway برسد. ممکن است اپراتور یا فیلترینگ آن آدرس، پورت یا الگوی ترافیک را مسدود کند، حتی وقتی Logs سالم است.
- مسدود بودن آدرس‌های Railway در برخی شبکه‌ها ممکن است؛ پس Deploy موفق، اتصال را تضمین نمی‌کند.
- تنها آزمایش واقعی: لینک را در تلگرام روی همان اینترنتی که قرار است استفاده کنید باز کنید.

## محدودیت‌ها

- IP و پورت عمومی ثابت و 443 را فرض نکنید؛ ممکن است عوض شوند و لینک باید به‌روز شود.
- مصرف شبکه، CPU و حافظه روی Railway صورت‌حساب دارد؛ قیمت‌ها و سهمیه پلن‌تان را در پنل ببینید. ترافیک پروکسی ممکن است سریع مصرف شود.
- من نتوانستم Docker build واقعی را اینجا اجرا کنم (شبکه ساندباکس بسته بود). منطق `entrypoint.sh` با یک mtg ساختگی تست شد، ولی Build واقعی را اولین‌بار خودتان روی Railway می‌بینید.
- این راهنما بر اساس ظاهر فعلی Railway نوشته شده؛ اسم دکمه‌ها ممکن است کمی تغییر کند.
